# L2 RAG 记忆卡

> 用途：不要反复读长笔记。先合上笔记，用这张卡自测；想不起来再看。

## 一句话

RAG = 先查资料，再让模型照着资料回答。

## 一张图

```text
文档 -> 加载 -> 分块 -> 向量化 -> 存储
问题 -> 向量化 -> 检索 top-K -> 拼进 prompt -> 模型生成回答
```

## 5-4-3-2-1

### 5 步

1. 加载
2. 分块
3. 向量化
4. 存储
5. 检索

再加 1 步：生成。

### 4 个设计选择

- chunk_size 和 overlap 怎么定
- 用哪个 embedding 模型
- top-K 和相似度阈值怎么定
- 要不要混合检索 / rerank

### 3 个坑

- 切太小：语义碎，检索到的片段不完整
- 切太大：噪声多，模型抓不到重点
- 只靠向量：精确匹配差，数字、代码、专有名词容易漏

### 2 个对比

- RAG vs 微调
- RAG vs 关键词搜索

### 1 个公式

```text
cos(A, B) = (A · B) / (|A| * |B|)
```

越接近 1，语义越相似。

## 30 秒口述稿

RAG 是检索增强生成。先把文档切块、向量化、存进向量库；用户提问时，把问题也向量化，检索最相关的 top-K 片段，再把这些片段拼进 prompt，让模型参考着回答。它适合私有知识、经常更新的资料，优点是成本低、可溯源，缺点是检索不准会带偏模型。
