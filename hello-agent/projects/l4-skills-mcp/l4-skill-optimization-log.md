## 第二轮优化（→ 82.7，+2.8）

- **日期**：2026-09-07
- **改了哪些**：
  - **R3（5ba3c10，dim2/dim6）**：通路 A/B 选择阈值量化（小 = 单章 / ≤12 页 / 一次性 → A；大 = 整份课件 / 多章 → B）；`check_coverage.py` 整体重写，从只认旧 `term_table` 块改为对齐现行 schema（para/heading/exam/figure/table），并去掉静默吞默认文件。冒烟 86% → 实测 **22/22 = 100% GOOD**。
  - **R4（2703108，dim2）**：考点模式的覆盖口径量化——**不套复习模式的 ≥85%**（回忆题只命中讲义 6/22 页时套了会误报），达标 = 命中讲义页全覆盖 + 文末写 **A3 覆盖范围声明**；`check_coverage.py` 路径自动定位 skill 根目录，任意目录可跑。
- **为什么这样改**：R2 之后实测（p1-r2）发现覆盖率工具**仍然对不上 schema**（dim2/dim6 的根），说明文档修得再好、工具和文档不一致整条工作流还是断的；R4 验证（p2-r4）又暴露"考点模式无达标线"会让执行体自己发明规则——所以把口径写死进 SKILL。

## 总结

- **失败处理要写成 if→then 显式分支表，而不是散在"注意事项"里的软话**——执行时碰到故障才知道停下、找兜底，这一条从 5 分涨到 8 分，是本次最大杠杆。
- **检查点必须用 🔴/🛑 这类显性视觉标记**，"必须…否则…"的措辞 LLM 扫描时会漏；加上标记后执行体真的会在没拿到材料前停下。
- **工具必须和文档里的 schema 对齐**，否则写得多漂亮，工作流里那条"跑覆盖率"的步骤还是断的（0% 误报的根因）；文档驱动 + 工具可执行，缺一不可。
- **每轮只改一个维度、改完必须 spawn 独立子 agent 真跑一遍**，分数才不会是自己改自己评的乐观偏差——R2 修完的"覆盖 100%"和 R4 修完的"考点口径"都是实测跑出来的，不是估计。
- **评分分数能落到具体哪一行改动，才有意义**：75.7→82.7 每一步 Δ 都能对应到一个 commit 和一处真实故障修复。
