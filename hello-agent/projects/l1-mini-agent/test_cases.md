# L1 测试用例

## 测试1：单工具调用

```
输入：1加2乘以3等于多少？用计算器算一下
预期：调 calculator("1+2*3")，返回 7
实际：✅ 通过
调用工具：1 次 | 步数：2
```

模型先调计算器得到结果，再组织语言回答。

## 测试2：多工具并行

```
输入：北京和深圳今天天气怎么样？
预期：同时调 get_weather("北京") 和 get_weather("深圳")
实际：✅ 通过
调用工具：2 次 | 步数：2
```

模型一轮内并行调用两个工具，收集结果后汇总回答。

## 测试3：零工具直接回答

```
输入：你好，请用一句话介绍下Python语言
预期：不调任何工具，直接回答
实际：✅ 通过
调用工具：0 次 | 步数：1
```

模型判断问题不需要工具，跳过 tool_calls 分支，一步返回。

## 测试4：工具报错（边界/异常）

```
输入：帮我计算这个：abc + 123
预期：calculator 返回错误信息（表达式包含不允许的字符），agent 把错误反馈给用户，不崩溃
实际：✅ 通过
调用工具：0 次 | 步数：1
```

模型直接判断表达式非法，没有调用 calculator，直接告诉用户无法计算。agent 未崩溃，但未实际触发工具报错路径——calculator 的输入校验没被走到。这个测试暴露了一个空隙：当模型自行判断输入不合法时，工具的错误处理代码就是死代码。后续 L2 可考虑构造一定会触发工具报错的用例（如让模型先调 calculator 再给非法输入）。

## 测试5：超长输入（边界）

```
输入："请帮我计算：" + "1+1, " * 500 + "最后再加2"（约4000字符）
预期：agent 不崩溃，能正常响应
实际：✅ 通过
调用工具：1 次 | 耗时 2.7s | 步数：2
```

agent 正常处理超长输入，成功计算并返回结果 402，未出现 OOM 或异常退出。
