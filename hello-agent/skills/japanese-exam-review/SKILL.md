# 日语考试复习文档生成器

## 概述

为软件工程中日合作办学项目的学生，根据日语授课的 CS 专业课课件和历年试卷，自动生成复习文档 PDF。支持 PDF 讲义和 PPTX 两种课件格式。

**核心设计：全 Skill 只有一套版式（统一排版标准），没有第二套。** 排版引擎是 `scripts/guide_style.py`（单字体 SimSun + 克制配色）。内容有两条"制作通路"：

- **通路 A 直写**（单次/小课件）：直接写一个 `build_*.py`，按阅读顺序调用引擎方法，想怎么组织就怎么组织。
- **通路 B JSON**（大课件/批量/需迭代复用）：写一份极简内容 JSON，由薄渲染器 `scripts/path_b_render.py` 映射回引擎。

**A 和 B 共用同一引擎，产出版式完全一致**（可自行复核：`output/sample_a.pdf` 与 `output/sample_b.pdf` 逐页比对，两册相同）。复习文档、考点解析、附录索引——无论生成什么，都只允许用这套版式元件。

按“文档重点从哪来”分 **2 种内容模式**（决定组织主线；两者都只用同一套版式 + A/B 任一通路，模式与通路正交）：

- **复习模式（讲义驱动）**：手头只有讲义 → 按讲义顺序逐章梳理，覆盖 ≥85%，★/红字只标“講義重点”。
- **考点模式（试卷驱动）**：投入了真实试卷材料（自己或同学的 PDF / 照片 / 回忆题都算）→ 先抽成**考点库**，再以考点为主线组织文档——命中的章节靠前、红字【試験】写明依据、末尾附 用語索引 / 試験対策。

风格校准样张：`output/sample_a.pdf`（直写 A）与 `output/sample_b.pdf`（JSON B），两册逐页相同。新产出生成后应翻一遍，与样张"同味"。

## 触发条件

同时满足以下两个要素时触发：

**要素 A — 日语相关**：提及"日语""日文""日本語""Japanese""Japan"，或日本学校/教师/教材/考试/授课

**要素 B — CS 专业课**：提及计算机网络、数据库、操作系统、数据结构、算法、软件工程、编程语言（Java/C/Python 等）、计算机组成原理、编译原理等

> "帮我把计算机网络PPT整理成复习文档" ❌（未涉及日语）
> "帮我学日语语法" ❌（不是专业课）

## 统一版式（全 Skill 唯一排版标准，勿另起风格）

排版由引擎 `scripts/guide_style.py` 决定。**你唯一能用的"版式元件"就是下表——A 直写对应引擎方法，B JSON 对应块类型。除此之外不要发明任何新排版**（不加新颜色、新字体、背景框、图标、装饰线）。

| 元件 | A 直写方法 | B JSON 块 | 用途 |
|------|-----------|-----------|------|
| 封面 | `title_page(jp,cn,en,sub,tagline,meta_rows)` | `cover{}` | 三段式标题 + 信息条 |
| 目次 | 手工 + `make_table` | `toc[]` | 章索引 |
| 章标题 | `chapter_title(num,jp,cn,stars)` | section 顶层字段 | 每章新页：17pt 藏青日文 + 红色中文副题 + 重要度 |
| 小节 | `h2(text)` | `heading level2` | 章内小节（如 1.1） |
| 中文正文 | `body_cn(text)` | `para kind=cn` | 中文流畅叙述（深棕） |
| 日文关键句 | `body_jp(text)` | `para kind=jp` | 需背的日文句（藏青），行内可带【中】译 |
| 中性正文 | `body(text)` | `para kind=note` | 次要说明（灰） |
| 表格/术语表 | `make_table(headers,rows,col_widths)` | `table{}` | 深藏青表头 + 隔行浅灰 + 边框 |
| 讲义原图 | `add_figure(path,caption_cn,caption_detail,w)` | `figure{}` | 截图 + 红▲主图注 + 灰细说明 |
| 考点红字 | `exam(text)` | `exam{}` | 自动加【試験】前缀，红色 |
| 分隔线/页脚 | `hr()` / 自动 | 自动 | 页脚页码引擎自带 |

**排版纪律（违反即返工）：**

1. **单字体**：只用 SimSun。禁止 `<b>`/`<font>`/换字体等强调手段（引擎已统一把 `・` 换成 `·`）。强调靠"藏青/红/粗细位置"，不靠字型。
2. **颜色三组**（引擎写死，写作时不要指定颜色）：藏青系 = 标题 + 日文关键句；**红色只能给【試験】考点和 ▲图注**；灰色 = 次要说明；正文 = 深棕/深灰。
3. **节奏固定**：章标题 → 小节 h2 → 概念正文 → 原图+红▲图注/灰细注 → 术语或对比表 → 红字考点收尾。
4. **标配结构**：封面 → 目次 → 各章 → （试卷模式）附录：全用語索引 / 試験対策まとめ。
5. **单元格双语换行**：表格内一行日文一行中文用 `\n`，格式 `日文原文\n【中】中文翻译`（引擎支持 `\n`）。正文段落一个逻辑点一段。

## 内容写作规范

1. **双语可读**：中文为理解主干，日文术语给原词、标题中日双写，保证遮住中文能对得上考试里的日语表述。
2. **正文两种写法，同一文档内统一其一**：
   - **(a) 中文主述 + 括注**：中文流畅正文，关键术语首次出现括注 `（日本語）`，重点记忆句单列一条 `kind=jp` 日文句。
   - **(b) 全对照**：日文一段（`kind=jp`）+ 中文一段（`kind=cn`）成对（样张 `output/sample_b.pdf` 即此风格，照它写）。
3. **术语准确**：与课件原文一致；中文用大陆 CS 标准译名。
4. **表格按需**：适合集中对比/分类/记忆才做表（回線 vs パケット、TCP vs UDP…）。説明/对比列必须中日双语。
5. **图片精选**：只放架构图/拓扑图/流程图/关键公式表截图；小图标、Logo、装饰图、重复标题条一律舍弃。无重点图就不放，不凑数。图注 = 红▲一行主图注 + 灰字细说明（指出考什么）。
6. **无遗漏**：逐页对照，非内容页（目录、测验链接、结尾总结）除外；内容覆盖 ≥85%。

## 考点与重要度（★ 和红字必须「有依据」）

- **考点模式（投入了真实试卷材料）**：无论材料是 `exams/` 的 PDF/扫描，还是对话里的照片/回忆版文字，一律抽成**考点清单（考点库）**。★ 重要度和每个红字【試験】**必须取自该清单**，写明依据如 `20XX 大問X`；回忆版题目写“同学回忆 · 講義重点”。**禁止**编造“考过/常考”。
- **复习模式（无试卷）**：★ 和红字只能依据讲义内明确复习要点、小测题、反复强调处，措辞标“講義重点”，**不得**伪造具体年份题号。

## 工作流程：先解析，再选 A/B

### 0. 解析课件（两通路共用）

- PDF 讲义：`python scripts/parse_pdf_lecture.py`
- PPTX 课件：`python scripts/parse_ppt.py`

输出 `output/parsed_ppt.json`；图片存 `output/images/`（同名多页多图：`{课件}_p{页}_img{n}.png`）。

有试卷时再跑 `python scripts/parse_pdf.py`（试卷目录 `exams/`）→ `output/parsed_exams.json`，人工/脚本汇总成考点清单。

选图：从 `output/images/` 挑宽图（排除 719×56 之类重复标题条、24×24 图标），输出选用清单。

### 考点模式：收试卷材料 → 抽考点库（做文档主线）

材料**不挑格式，只挑真不真**——真实题目能送到这台机器就行：

- `exams/` 里的 PDF / 扫描件 → 跑 `python scripts/parse_pdf.py` → `output/parsed_exams.json`；
- 对话里直接给的照片 / 截图 → 逐题读图转写；
- 同学口述 / 手打的回忆题 → 直接按文字逐条录入（标“回忆版”）。

三种来源都抽成**同一份考点库 JSON**，每条含 `来源`（如 2024 期末 / 同学回忆）、`题型 / 题号`、`考点术语`、`频次`、`重要度 ★`。**考点库是考点模式排文档的唯一主线**——哪些章靠前、哪些给 ★★、哪些配红字【試験】、末章附录写什么，全由它定，不许凭空加。

**考点模式的覆盖口径（区别于复习模式的 ≥85%）**：达标 = 试卷/回忆命中的讲义页**全部覆盖**（逐条核对，每条红字都能在正文/附录找到对应），**未命中的讲义页不硬凑**——复习模式的 ≥85% 只适用于"讲义全扫"的复习模式，套到考点模式会误报 NEEDS WORK。收尾时在文末写**「覆盖范围声明」**：列出命中了哪些讲义页、哪些因回忆未涉及而跳过。

### 通路 A — 直写（单份 / 小课件 / 想自由排版时默认）

1. 在 `scripts/` 现写 `build_review.py`：
   ```python
   import os
   from guide_style import SEPDF
   BASE = os.path.dirname(os.path.dirname(os.path.abspath(__file__)))
   IMG = os.path.join(BASE, "output", "images")
   pdf = SEPDF(); pdf.set_margin(15)
   # 按"统一版式"节奏直排：封面 → 目次 → chapter_title → h2 → body_cn/body_jp → add_figure → make_table → exam
   # add_figure 传完整图片路径，如 os.path.join(IMG, "2024CN_02(1)_p4_img26.png")
   pdf.output(os.path.join(BASE, "output", "review.pdf"))
   ```
2. 运行 `python scripts/build_review.py`；**🔴 目验** `output/review.pdf` 与样张同味，不符先回改，不交付。
3. 参照 `scripts/build_sample_a.py` 学习写法和节奏。

### 通路 B — JSON（大课件 / 批量 / 需覆盖率迭代）

1. 写内容 JSON（规范与示例见下、字段见 [path_b_render.py](scripts/path_b_render.py) 头注释）。
2. 覆盖核查：`python scripts/check_coverage.py <content.json>`（复习模式目标 ≥85%；脚本自动定位 skill 根目录，任意目录可跑）。**口径 = 页文本与内容术语池 ≥1 词命中即算覆盖（宽松：封面/近空页命中会推高数字——重点看列出的 NO coverage 页）**。报 0% 或不达标 → 查「失败模式与兜底」表。
3. 渲染：`python scripts/path_b_render.py <content.json> -o output/review.pdf`。
4. **🔴 目验** 与样张同味，不符先回改，不交付。参照 `output/sample_b.pdf`。

## 通路 B 内容 JSON 规范（极简）

```json
{
  "cover": {"jp": "", "cn": "", "en": "", "sub": "", "tagline": "", "meta": [["标签", "值"], ["标签", "值"]]},
  "toc": [["1", "章主题", "★★★"], ["2", "章主题", "★★"]],
  "sections": [
    {"num": "02", "jp": "章名（日文）", "cn": "章名（中文）", "stars": "★★★", "blocks": [ ... ]}
  ]
}
```

| 块 | 字段 |
|----|------|
| `{"type":"para","kind":"cn"\|"jp"\|"note","text":"…"}` | kind: cn=中文正文 / jp=日文关键句 / note=灰色次要 |
| `{"type":"heading","level":2,"text":"1.1 …"}` | 小节标题（level≥3 用更小字号） |
| `{"type":"table","headers":[…],"col_widths":[…],"rows":[[…],[…]]}` | 首行表头；单元格可用 `\n` 写 `日文\n【中】中文` |
| `{"type":"figure","file":"xx_p4_img26.png","w":140,"caption_cn":"红▲主图注","caption_detail":"灰字细说明"}` | file 相对 `output/images/` |
| `{"type":"exam","text":"考点（依据试卷/讲义）"}` | 红字，自动加【試験】前缀 |

示例 `examples/content_b_example.json`（生成出的 PDF 即 `output/sample_b.pdf`，与直写版 `output/sample_a.pdf` 逐页一致）。**schema 就这么多块，别加新类型。**

## 质量要求（验收）

1. 版式：只用上表元件，无自创排版；红色只出现在考点和图注。
2. 双语：术语准确、说明可懂、标题中日；表格説明列中日双语。
3. 考点：★ 和红字有依据（试卷真实考点或讲义明确要点），不编造。
4. 覆盖：**复习模式**＝逐页对照、无整页遗漏、≥85%（B 用 check_coverage.py）；**考点模式不套 85%**＝命中的讲义页全覆盖、未命中页不硬凑，文末写覆盖范围声明。
5. 图：只放重点图，图注点出"考什么"。
6. 全程只读真实来源（课件/试卷），不虚构术语与事实。

## 失败模式与兜底（先想失败再动手）

遇到下表症状按行处理，**不许硬闯、不许静默跳过**：

| 症状 / 触发 | 一线处理 | 仍失败 → 兜底 |
|------------|---------|--------------|
| 解析 0 页 / 文本乱码（PDF 文字层抽不出或日文错乱） | 换 PyMuPDF 直抽正文，或换 parse 脚本重试 | 告知用户该讲义无法自动读取，请提供文字版/清晰扫描；**不得**凭空编内容硬生成 |
| 本会话读不了图（无视觉） | 用 PyMuPDF 图块位置 + 邻近文字佐证图内容，只选可确证图 | 宁缺毋滥：重点改以文字/表格承载，不放入未经核实的图 |
| 讲义本页无重点图 | 直接不放图（不凑数） | — |
| 覆盖 <85%（逐页对照或 check_coverage） | 对照解析逐页补漏 → 重跑覆盖率 | 解析本身不全 → 按实际可读页数说明覆盖口径并如实告知，不强撑数字 |
| check_coverage.py 报 0% / 报错 | 确认 content.json 用的是现行 schema 块（`table`/`para`/`figure`/`exam`），再重跑 | 手工逐页对照做覆盖判断 |
| 渲染报错 / missing glyphs 缺字形 | 按警告改写避开缺字（`・` 已自动转 `·`；`⇔` 等改换说法） | 把具体缺字报给用户定替换词；**不**为此引入第二字体 |
| fonts 缺失（"字体注册失败"） | 把 `simsun.ttc` 放进 `fonts/`（引擎自动取 `simsun_extracted.ttf`，回退 ttc） | 停止并提示装字体 |
| 考点模式只有回忆版、无正式卷 | 红字/★ 标"同学回忆 · 講義重点"，**不**写正式年号题号 | 连回忆题都没有 → 退回复习模式只标講義重点 |
| 用户要的课本机没有对应课件/试卷 | 🔴 前置确认拦下并索要材料 | **禁止**拿其他科目样张或通用知识硬套成该课的 PDF |

## 注意事项

- **字体/缺字形**：引擎加载 `fonts/simsun_extracted.ttf`（回退 `fonts/simsun.ttc`）；缺字形警告＝内容用了 SimSun 没有的字 → 按「失败模式与兜底」表改写。**只用 SimSun，不要引入 Noto 或任何第二字体。**
- **脚本位置与运行目录**：均在 `scripts/`，图片在 `output/images/`；解析脚本会覆盖 `output/parsed_*.json`。脚本里的 `output/` 是相对 skill 根目录的路径——**请在 skill 根目录运行**（如 `python scripts/parse_ppt.py`）；`check_coverage.py` 例外，已自动定位 skill 根目录，任意目录可跑。
- **只允许两条渲染通路**：guide_style（A 直写）或 path_b_render（B JSON）。不要引入 reportlab 或其它 PDF 库——版式统一全靠这套引擎，加第二个渲染器会让同一份内容出两种样子。
